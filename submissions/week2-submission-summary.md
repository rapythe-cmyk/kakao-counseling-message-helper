## v0.1에서 실제로 되는 기능
1. 샘플 상담 상황을 선택하거나 직접 입력할 수 있다.
2. 안내 유형과 말투를 선택해 카카오톡 안내문 초안을 생성할 수 있다.
3. 효과 보장, 최상급 표현, 개인정보 요청, 가격 단정 표현을 검수할 수 있다.
4. 생성된 안내문을 복사하거나 브라우저에 저장할 수 있다.
5. 최근 저장 초안 5개를 저장 이력으로 확인할 수 있다.
6. 샘플 데이터, 직접 입력, 검수, 개인정보 제외, 발송 제외 기준을 QA 상태로 확인할 수 있다.

## 2주차 작업노트 7단계 진행 기록

### [단계 1] Claude Code로 우선 만들어보기
- 1주차 아이디어인 `상담 카톡 안내문 생성·검수 시스템`을 기준으로 v0.1 웹앱을 만들었다.
- 사용자가 상담 상황, 안내 유형, 말투를 선택하면 바로 카카오톡 답변 초안이 생성되도록 했다.
- 첫 화면에서 실제 사용 흐름이 보이도록 입력 영역, 초안 결과, 검수 결과를 한 화면에 배치했다.

### [단계 2] 데이터 연결하기
- `src/sample-cases.json`에 한의원 상담 상황 샘플 데이터를 분리했다.
- 샘플 데이터에는 초진 문의, 예약 안내, 비용 문의, 내원 전 준비, 시술 후 안내, 예약 변경 상황을 넣었다.
- 직접 입력 모드도 추가해서 샘플에 없는 실제 상담 상황도 넣을 수 있게 했다.

### [단계 3] DB·API·MCP 연결 + QA
- 이번 v0.1에서는 외부 DB/API/카카오톡 발송 연동은 제외하고, 브라우저 저장소를 임시 저장 DB처럼 사용했다.
- 생성한 초안은 최근 5개까지 저장 이력으로 남게 했다.
- 화면 안에 QA 상태 패널을 넣어 샘플 데이터, 직접 입력, 위험 표현 검수, 자동 발송 제외, 개인정보 저장 제외, 담당자 최종 확인 문구를 확인할 수 있게 했다.

### [단계 4] 항로별 필요한 기능 배포
- 업무 도입 항로에 맞춰 실제 반복 업무인 카카오톡 상담 답변 초안 작성과 발송 전 검수에 집중했다.
- 병원 운영자가 바로 쓰는 흐름을 기준으로 안내 유형, 말투, 위험 표현 체크, 복사 기능을 우선 구현했다.
- 실제 환자 개인정보 저장, 로그인, 결제, CRM 연동은 v0.1 범위에서 제외했다.

### [단계 5] 사용자에게 보여줄 준비하기
- 화면 상단에 서비스 이름과 목적을 명확히 보이게 정리했다.
- 상담 입력 → 초안 생성 → 위험 표현 검수 → 복사/저장 순서로 사용 흐름을 정리했다.
- 제출용 화면 캡처를 `screenshots/week2-v0.1-kakao-counseling.png`로 저장했다.

### [단계 6] 보안 점검 - 출시 전 마지막 관문
- 코드 안에 API 키나 비밀값을 넣지 않았다.
- 환자 이름, 전화번호, 주민번호 같은 실제 개인정보 저장 기능은 넣지 않았다.
- 카카오톡 자동 발송을 막고, 모든 문구는 담당자 확인 후 발송하는 초안으로 표시했다.

### [단계 7] Vercel 배포 - 내 서비스를 인터넷에 올리기
- Vercel CLI 로그인 상태는 확인했다.
- `npm run build`로 배포용 빌드가 성공하는 것을 확인했다.
- 실제 Vercel 공개 배포는 계정의 기본 팀/스코프 설정이 없어 막혔다. 에러 내용은 `teamId` 또는 `defaultTeamId`가 필요하다는 내용이다.
- 그래서 현재 제출 링크는 로컬 실행 URL인 `http://localhost:5173/`로 남겼고, Vercel 계정 설정이 해결되면 같은 빌드 결과물을 바로 배포할 수 있다.
